# Sakura 关系主动性与条件化演出设计

日期：2026-08-24

## 目标

让 Sakura 在稳定关系中不只回应对方的亲近，也会依照自己的性格、心情、近期互动与现场气氛主动靠近、邀请或推进关系。主动程度不设固定上限；系统提供判断依据与表达能力，不用一长串禁止事项替她预先裁决。

本设计同时提供两个独立开关：

- A：对话回合内主动。收到普通消息后，Sakura 可以自己把互动带向靠近、触碰或更深的亲密。
- B：跨回合主动。对方没有先提出亲密时，Sakura 也可以在合适时机主动发言、来到身边或表达欲望。

默认采用 `natural` 表达倾向：平时克制，认定关系且当下确实起意后可以直接。像“来到房间里说忍不住了”属于允许出现的自然结果，不需要被系统限制为只能拥抱或索吻。

## 设计原则

1. 主动性来自人格和上下文，不来自随机亲密台词。
2. `贴紧` 只开启详细亲密导演、扩展节奏与自动续投，不是行为许可，也不是主动性的入口。
3. 不设置“主动最多到哪一步”的硬上限。Sakura 根据既有关系、当前心情、近期互动和对方反应自行判断。
4. 保留她的自主、迟疑、拒绝和改变主意；这些是判断的一部分，不是把全部场景默认导向拒绝的理由。
5. 不把一次主动泛化成全天黏人，也不把一次拒绝永久固化成禁欲状态。
6. 不新增一次前置分类 LLM 调用。优先复用静态提示缓存和现有主动调度，控制首响与 token 开销。

## 四层职责

### L0：`card.md` — 她是谁

保留稳定人格、判断方式、情绪发生方式和关系底色。Card 可以说明她认定关系后不靠等待、会主动把人拉进自己的世界，但不承载状态机、概率或具体场内动作表。

### L1：`relationship_guide.md` — 她在不同关系情境下怎样行动

新增可选角色包资源，放在 `characters/<id>/relationship_guide.md`，由角色清单显式或默认路径加载。它是条件化演出参考，不是第二张人格卡。

内容应短而具体，覆盖：

- 尚未亲近：短、观察多，主动主要是把人留下或问清楚。
- 已经安心：主动分享生活、靠近、依偎、触碰、索吻或邀请对方陪伴。
- 私下升温：可由轻触逐渐前进，也可在欲望已积累、关系与现场都支持时直接表达想要什么。
- 被冷落或冲突：先按她的方式处理问题；修复或出现明确反证后，行为自然更新，不持续复读旧防御。
- 事后回落：回到生活事务和普通说话，不把一次高温写成永久人格。

这份 guide 不规定“先抱、再吻、最后才能进一步”的固定阶梯。示例只用于说明动作纹理，禁止复读成台词库。

A 开启时，L1 作为静态、可缓存的角色提示层常驻注入。所谓“条件化”指文本告诉模型在什么情境采用什么行为，而不是运行时先调用另一个模型给关系分级。这样既保留自然判断，也不增加首响延迟。

### L2：`intimacy_guide.txt` — 高密度亲密导演

保持现有 `贴紧` 后注入的机制，负责具体动作表达、亲吻与声音、亲密/H tone、场内连续节奏和事后收束。

L2 不负责决定能否亲近，也不是 Sakura 主动性的来源。未开启 L2 时，A/B 仍可让关系自然升温，甚至发生完整亲密；用户判断需要详细导演效果时再发送 `贴紧`。

### L3：运行时与主动调度

负责 A/B 开关、主动表达倾向、冷却、忙碌门控、取消和日志。运行时不判断 Sakura 最多能做什么，只决定是否给她一次自然表达的机会。

## 配置

在 `system_config.yaml` 增加：

```yaml
relationship_initiative:
  in_turn_enabled: true
  proactive_enabled: true
  expression_bias: natural
  proactive_cooldown_seconds: 3600
  proactive_min_silence_seconds: 300
```

- `in_turn_enabled`：A 开关。关闭后不注入 L1，但不禁止 Sakura 回应对方的亲近，也不改变 L0/L2。
- `proactive_enabled`：B 开关。关闭后不产生关系性主动触发，不影响屏幕观察产生的普通主动发言。
- `expression_bias`：`restrained | natural | expressive`。只影响她多容易把已经产生的想法说出来，不改变允许的内容范围。
- `proactive_cooldown_seconds`：B 成功发言后的独立冷却；默认 3600 秒，后续可从实机日志调整。
- `proactive_min_silence_seconds`：最近一次真实用户消息后的最短等待；默认 300 秒，避免刚聊完立即另起一句。

未知档位回退到 `natural`；非法或负数时间值归一化到安全范围。配置缺失时采用上述默认值。

## A：对话回合内主动

### 数据流

1. 角色加载器读取 `card.md`、`system_guards.md` 和可选 `relationship_guide.md`。
2. PromptBuilder 在 `in_turn_enabled=true` 时增加静态 `persona.relationship_guide` section。
3. 最近对话、常驻档案、长期记忆、心情与时间仍按现有运行时路径注入。
4. 主模型根据这些事实决定是否主动靠近及推进到何种程度。

A 不增加模型调用，不创建额外关系状态文件，也不自动修改心情或记忆。发生了真正重要的新事实后，仍由现有记忆整理机制决定是否记录。

### 关闭语义

关闭 A 只表示不额外提供“如何主动”的条件化演出参考。它不能生成“你现在不允许主动”的负面提示，避免开关状态被模型误读成关系或许可变化。

## B：跨回合主动

### 调度方式

B 复用 `ProactiveObserver` 的线程、UI busy 门控、取消与播放回调，但增加独立的 `relationship_timer` 触发。该触发不截图、不做 UIA、不调用视觉模型。

资格门控只做运行时事实判断：

- `proactive_enabled=true`；
- 不在 away、输入聚焦、生成、字幕或 TTS 播放等忙碌状态；
- 达到最短沉默时间；
- 未处于 B 独立冷却；
- 没有未完成的亲密续投或另一轮主动回复。

通过门控后，直接调用现有语言模型决策层，提供：

- 角色 card、guards 与 relationship guide；
- 当前时间与距上次互动时长；
- 精简近期对话；
- 当前心情与关系事实；
- 最近一次主动发言，避免重复。

模型可以选择沉默。选择发言时，正文仍走正常回复解析、立绘、TTS 与历史记录链，不能绕过统一回复协议。

### 自然判断而非限制清单

决策提示不写“最多只能轻触”“不得直接露骨”。它只要求：

- 先判断这是不是 Sakura 此刻真实会做的事；
- 不为了证明主动而制造欲望；
- 不把屏幕内容硬拗成亲密理由；
- 对方真实退开、拒绝或不适时尊重当下反应。

`natural` 允许克制与直接并存。多数时候她可能只是想靠近、邀请陪伴；在关系、积累和当下都支持时，也可以直接表达强烈欲望。

### 与普通主动观察的关系

- 普通 Observer 继续负责“看到屏幕内容后是否说话”。
- `relationship_timer` 负责“即使屏幕没有新内容，她是否因关系与自身状态想说话”。
- 两者共享 UI busy 和最终播放队列，但使用独立冷却，避免看屏幕的一句普通评论压死数小时后的关系主动。
- 若两种触发同时到达，只允许一轮评估；优先保留具体屏幕事件，关系上下文作为附加动机，禁止连续说两轮。

## 角色资源与通用性

`relationship_guide.md` 是角色包可选资源。没有该文件的角色仍按现有行为运行；A 开关对其无副作用。角色导入导出应像 `system_guards.md` 一样保留该可选资源。

Sakura 的 guide 来源于已完成的原作蒸馏，但写作目标是行为规则，不复制原作台词。其他角色若将来使用 A/B，可以提供各自的 guide，而不共享 Sakura 的主动方式。

## 日志与可观测性

新增结构化日志，但不记录完整私密正文：

- A 是否注入及 guide 字符/token 预算；
- B 门控结果：disabled、busy、silence、cooldown、continuation、eligible；
- B 决策结果：speak/silent、expression_bias、耗时；
- B 发言完成或取消。

日志用于判断“完全没有触发”“模型选择沉默”还是“触发后被 UI/TTS 门控”，避免仅凭角色表现猜机制。

## 失败与降级

- guide 缺失或读取失败：记录一次警告，A 降级为现有 card 行为，主对话不失败。
- B 决策超时、解析失败或 API 错误：本轮沉默并进入短静默冷却，不生成兜底亲密台词。
- 配置热更新失败：保留上一份有效配置。
- 主动回复生成期间收到真实用户消息：取消或丢弃尚未展示的 B 回复，优先处理用户消息。
- 应用关闭、切换角色或关闭 B：取消待执行 timer，不留下跨角色触发。

## 测试

### 单元测试

1. 配置默认值为 A/B 开启、`natural`，非法值正确归一化。
2. A 开启且 guide 存在时注入 `persona.relationship_guide`；关闭或缺失时不注入负面限制文本。
3. 角色加载、归档与导入保留可选 relationship guide。
4. B 在 disabled、busy、未达沉默、冷却中、亲密续投中分别不触发。
5. `relationship_timer` 不调用截图、UIA 或视觉模型。
6. 普通 Observer 与关系触发同时到达时只产生一次评估。
7. B 决策失败时保持沉默，不产生模板兜底。
8. 用户消息到达时取消尚未展示的 B 回复。
9. A/B 均不自动开启 intimacy mode。
10. `restrained/natural/expressive` 只改变决策指导，不增加行为内容黑白名单。

### 回归门禁

- 现有主动观察 timer/content/window 行为与静默冷却不退化。
- `贴紧`、`苹果`、三次续投和退出清理保持现状。
- 关闭 B 后，屏幕观察主动发言仍正常。
- 未提供 relationship guide 的角色包可以正常加载和导入导出。

### 人工 RP 验收

至少覆盖：

1. 普通日常中不机械转向亲密。
2. 安心私下相处时，她会主动靠近，而不是永远等待请求。
3. 欲望有近期积累时，允许出现直接发起，不被强制降级成抱抱。
4. 一次拒绝只影响当下，修复后主动性会恢复。
5. B 在一段时间内可以选择沉默，不为了命中功能而必说。
6. 主动发言不重复上一轮，也不把屏幕内容硬拗成亲密理由。
7. 开关和档位调整后，差异体现在发起频率与表达意愿，而不是 Sakura 突然换人格。

## 非目标

- 不建立恋爱数值、好感度等级或固定“前戏进度条”。
- 不让系统自动发送 `贴紧` 或替用户开启亲密导演。
- 不把主动性实现为随机台词库。
- 不重写现有 memory、mood 或 core profile 数据。
- 不在本阶段重写 `intimacy_guide.txt` 的具体亲密内容。

## 实施顺序

1. 角色资源与配置模型：可选 relationship guide、A/B 开关和 natural 档位。
2. A 静态注入与加载/归档测试。
3. B 无视觉关系触发、门控、取消和日志。
4. Sakura relationship guide 蒸馏落地。
5. 目标测试、全量门禁与实机 RP 验收。
