# Sakura 亲密模式分层与第一阶段修复设计

日期：2026-08-24

## 目标

让亲密模式中的 Sakura 仍然保持完整人格、独立判断和退出权，同时减少误退出、强制推进、复读、TTS 串层与无人续投造成的延迟和 token 消耗。

亲密模式是用户主动选择的“导演增强层”，不是亲密许可、关系状态或行为能力的开关。未开启模式时，Sakura 仍可依据当前关系、记忆、当下意愿与对话，自然发生从日常触碰、前戏到完整性行为的任何互动；系统不得因为模式 inactive 而默认拒绝、降级关系或限制互动阶段。

第一阶段修复运行时高风险问题并建立分层边界，不直接覆盖现有 `data/intimacy_guide.txt`。后续在独立候选中重写 guide，经人工 RP 验收后再替换。

## 已确认的交互约定

- 整句 `贴紧`：由用户主动进入亲密导演模式，可带普通末尾标点。
- 整句 `苹果`：退出安全词，可带普通末尾标点；立即停止续投、退出模式并清理临时上下文。
- 包含这些词的普通长句不触发模式切换，例如“再贴紧一点”。
- 系统不因对话已经自然发展到前戏或性行为而自动开启模式；是否需要详细 guide 和自动续投，由用户自己判断。
- 未说 `贴紧` 不代表拒绝、未同意或尚未准备好，也不妨碍 Sakura 主动或接受亲密互动。
- 安全词不是拒绝的唯一表达。明确的“停下、不要继续、我不舒服”等仍必须零延迟停止；系统不得要求用户必须说出安全词。
- “好了、太好了、准备好了、待って、不行”等高歧义表达不再作为包含匹配的模式开关。只有语义明确的拒绝走紧急停止。

## 四层职责

### L0：角色人格

永远在场，来源为 Sakura card。亲密模式中允许压缩，但必须按段保留：

- 核心
- 能动性与判断
- 关系中的她
- 不要写成
- 双方意愿、迟疑时暂停、独立判断和退出权
- 反复读但不为了变化而强行改变真实态度

禁止继续使用“截取 card 开头固定字符数”的策略。

当前关系事实不由 card 硬编码。Sakura 对用户的关系认识以真实积累的近期对话、常驻档案和长期记忆为准；原作经历用于塑造人格，不能覆盖、重置或贬低当前已经形成的关系。心情与内心独白可以影响当下语气和节奏，但不能凭一次迟疑把既有恋爱关系改写成“需要重新认识”。

### L1：通用亲近场景导演

负责模式外也成立的恋人互动逻辑：拥抱、亲吻、深吻、身体试探、情欲升温、前戏乃至自然发生的性行为，都由当前关系、动作和双方反应继续。迟疑时放缓，明确不适时停止，避免机械升级，事后自然回落。它不负责入口词、计时器或 TTS 格式，也不得把模式状态解释为行为许可。

### L2：私密 guide

仅在模式 active 时注入，负责私密场景特有的表达强度、连续节奏与参考素材。它是可选增强：缺席时不禁止任何亲密行为。它不重新定义 Sakura 的性格，不承担同意、关系判断、状态机、续投计数或通用 JSON/TTS 协议。

第一阶段保留现有文件；第二阶段在独立候选文件中瘦身和重写，经用户验收后替换。

### L3：运行时与 TTS 协议

负责：

- `贴紧 / 苹果` 固定词和紧急停止识别
- 进入、续投、退出和自动关闭状态
- 续投 transient 生命周期
- tone 白名单
- `suppress_tts` 的显示/朗读路由
- 分段 JSON 合同

角色 card 和私密 guide 不重复这些机制。

## 第一阶段行为

### 进入与确认

`贴紧` 表示用户主动请求启用详细 guide、连续节奏和自动续投，不表示双方刚刚取得亲密许可，也不创建或升级关系。系统不再机械询问一次相同的模式确认。模式开启不等于后续每一步都自动许可：任何一方迟疑、退开、改变主意或表达不适时，Sakura 必须根据具体语境放缓、暂停或确认；单纯沉默不能被当作升级许可。

模式关闭时同样允许自然亲密。`persona.intimacy_entry` 只可解释约定词和可选增强，不得作为“等待许可”的保守人格层长期注入，更不得暗示深吻、前戏或性行为必须先开启模式。

### 自动续投

- 最多 3 次。
- 默认间隔为 20 秒、35 秒、60 秒。
- 续投信号要求“回应当前状态，必要时放缓、确认或自然收束”，不得强制推进到下一阶段。
- 每条续投消息标记为 transient。
- 用户发言、模式退出、取消、关闭窗口或新互动开始时停止相应计时器。
- 不允许出现“续投消息已发送，但状态已先失活、亲密 tone 被洗掉”的边界轮。

### 退出

- `苹果` 整句触发最高优先级退出。
- 明确拒绝或不适触发紧急退出。
- 退出在当前轮 prompt/tone 选择前生效。
- 退出后停止计时器、清零续投状态、移除 transient 续投消息并恢复日常 persona recipe。
- 下一轮日常上下文不得包含“推进亲密”的系统信号或私密 guide 正文。

### 人格保段

`soften_character_card_for_intimacy()` 改为标题感知的段落选择，而非截头。未知标题采用保守策略：若包含意愿、退出、判断、边界或反 OOC 关键词则保留。输出不得以孤立标题结尾，也不得把 handoff 元信息计入人格预算。

建议目标预算约 1100–1400 中文字符；节省 token 应优先来自减少续投和移除无关工具段，而不是继续削薄人格。

### TTS 合同

通用回复协议正式声明：纯动作或环境描写段可设置 `suppress_tts: true`，该段只显示不朗读；可听台词正常朗读。私密 guide 只给表达参考，不再独自承担这个跨层字段定义。

## 实现边界与分工

### Cursor

负责边界明确的状态机/UI 机械修改和测试：

- 固定退出词与紧急停止识别
- 三次递增续投
- transient 标记与清理
- 模式退出后的上下文隔离
- 对应单元/UI 测试

不得修改 Sakura card、私密 guide 或人格压缩策略。

### Codex

负责：

- 按段人格压缩
- prompt 文案与 L0/L1/L3 边界
- `suppress_tts` 通用合同
- 审查 Cursor diff
- 集成、全量测试、commit 与 push 决策

### Claude Code

只读架构审计已完成。本阶段不再重复调用 Opus，除非出现新的架构争议。

## 测试门禁

至少覆盖：

1. `贴紧` 整句进入；包含词的普通长句不进入。
2. `苹果` 整句立即退出；包含词的普通长句不退出。
3. 明确拒绝和不适无需安全词也立即退出。
4. “太好了、准备好了、好了吗”等不误退出。
5. 三次续投的间隔与上限正确，不存在状态/tone 冲突边界轮。
6. 续投信号退出后全部清理。
7. 亲密 persona 必须包含退出权、迟疑时暂停、不要写成和反复读关键约束。
8. 人格压缩结果不含 handoff 元信息，不以孤立标题结束。
9. `suppress_tts` 动作段不朗读，台词段正常朗读。
10. 模式退出后的日常轮不注入私密 guide 或续投信号。
11. 模式 inactive 时，日常触碰、亲吻、前戏与性行为均不因状态本身被禁止或降级。
12. 对话自然发展到性行为不会自动开启模式；只有用户整句 `贴紧` 才开启。
13. 当前关系事实以常驻档案、长期记忆和近期对话为准；心情或单轮迟疑不得重置关系。

目标测试通过后运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests\unit tests\integration tests\ui -q
```

## 成本与效果预期

自动续投由最多 8 次降为 3 次，是主要降本来源。配合 transient 清理和后续专用 recipe/guide 瘦身，完整亲密会话预计由约 72–88K input tokens 降至约 15–18K。人格预算略增是有意取舍：优先保证 Sakura 仍是同一个人，再从机制重复和无人续投中节省成本。

## 后续阶段

第一阶段实机验证稳定后：

1. 生成独立的 L1 场景导演候选。
2. 生成瘦身后的 L2 `intimacy_guide` 候选。
3. 进行多轮 RP 人工验收，检查主动性、边界、复读、节奏、TTS 和退出回落。
4. 用户明确认可后才备份并替换现有 `data/intimacy_guide.txt`。
